# Research Directions

## 目的

整理当前阶段的结论、已验证的问题、放弃继续优化的方向，以及下一阶段值得继续研究的方案。

这份文档不是实现说明，而是下一轮设计讨论的起点。

## 当前结论

### 1. 现有 `feature-driven` 路线不再是重点

已经做过的这些主题：

- `star_line_minimal`
- `star_line_spectrum`
- `wireframe_spectrum`
- `wireframe_inbound`
- `wireframe_ridge`
- `wireframe_pulses`

它们有一个共同问题：

- 画面主要表达的是“分析后的结果”
- 用户感知到的是节奏、响度、局部特征的映射
- 不是声音本身被直接呈现

这条路线可以保留，但不再是当前研究重点。

### 2. `wireframe_wavefront` 作为“信号直显”尝试，方向仍然不对

已经明确的问题：

- 波前像是从边缘“长出来”而不是穿过空间传播
- 传播到中间后方向性明显减弱
- 各处纹理趋同，容易变成规则的梳状结构
- 主层与历史层区分不清
- 显示的是“局部统计重构结果”，不是“正在传播的前沿”

结论：

- `wireframe_wavefront` 可以保留作实验记录
- 但不建议继续作为主方向投入

### 3. 当前阶段最值得转向的是“共振体 / 共振场”方案

用户对下面两个方向反应最强：

- `Chladni patterns / Cymatics`
- `Oskar Fischinger` 式视觉音乐

新的方向不再把默认视觉对象设为：

- 波形
- 频谱
- 线性传播的波前

而是把默认视觉对象设为：

- 被声音驱动的共振介质
- 或被声音激发的模态场

## 已形成的设计判断

### A. “看见声波”不是最直观的目标

问题在于：

- 波形本身也是一种抽象表示
- 人并不在自然经验中直接观察到音乐频率下的“声波曲线”
- 相对更直观的是：
  - 物体振动
  - 介质扰动
  - 共振图样

因此更合理的问题不是：

- 如何把声音画成波形

而是：

- 如何把声音作用于某种物体/介质/空间后的结果画出来

### B. Chladni / Cymatics 不只适用于单一正弦波

对于复杂音乐：

- 不应期待始终得到稳定、清晰、静态的几何花纹
- 更合理的理解是：
  - 模态竞争
  - 图样迁移
  - 共振状态切换
  - 能量在空间上的重新分布

因此，复杂音乐下的目标不应是：

- “每一刻都形成一个完美图样”

而应是：

- “看到一组模态如何被持续激发、切换、叠加、衰减”

### C. 多共振板不需要命中单一精确频率

每个共振体更像一个带宽有限的共振器，而不是只认一个频率点：

- `f0`：中心频率
- `Q`：品质因数/带宽
- `gain`：敏感度
- `modes`：内部模态集合

音乐里即使没有精确的 `500Hz`，只要 `500Hz` 附近有能量，该共振体就会响应。

因此，后续如果做多共振板系统：

- 应按频带组织
- 不应按单频点组织

## 下一阶段候选方案

### 方案 1：Chladni-Inspired Field

这是当前优先级最高的方向。

#### 核心思路

- 画面表示一整块二维介质或若干个共振板
- 输入音频不直接显示为波形
- 音频驱动多个模态分量
- 最终显示：
  - 位移场
  - 结线场
  - 等值线
  - 颗粒聚集图样

#### 预期优势

- 更直观
- 更接近物理直觉
- 复杂音乐下也有合理解释
- 比波形/频谱更接近用户当前兴趣

#### 关键设计问题

- 单板还是多板
- 每块板是显示位移、结线，还是颗粒聚集
- 频带如何分配到不同共振体
- 模态数量如何控制，避免过乱

### 方案 2：共振体阵列

#### 核心思路

- 不做完整二维连续场
- 画面中放置多个可共振对象：
  - 板
  - 膜
  - 弦
  - 网格面
- 每个对象负责一段频带或一组模态

#### 特点

- 更容易控制
- 更适合复杂音乐的分层表达
- 工程上比完整场模拟更容易收敛

#### 风险

- 如果布局不当，容易退化成“多个频带面板”
- 必须避免看起来像仪表盘

### 方案 3：介质扰动 / 声场显影

#### 核心思路

- 画粒子、烟、纤维、液面、密度场
- 画的是声音作用后的扰动，而不是声音图表

#### 特点

- 更艺术化
- 空间感强

#### 风险

- 很容易失去结构可读性
- 也容易变成“漂亮但泛”的音频反应效果

### 方案 4：Web 实时预览器

这不是视觉方案，而是研发方式。

#### 判断

- 当前处于“映射逻辑探索期”
- 继续 Python 离线逐帧导出，试错效率过低

#### 建议

- 新增一个 Web 实时预览器
- 用于调试新主题，尤其是共振场类主题
- 最终成片仍保留离线导出链路

#### 技术倾向

- 实时预览优先 Web
- 最终导出保留现有工具链

## 对现有实现的复用判断

### 可直接复用

- 音频加载与分析流程
- CLI / 导出 / ffmpeg 流水线
- 主题注册机制
- 配置系统
- 渲染框架基础设施

### 部分可复用

- `analysis.py` 中已有的：
  - waveform windows
  - left/right signal
  - bands
  - rms
  - centroid

这些可以作为新主题的输入来源，但不应约束新主题必须沿用旧的映射逻辑。

### 基本不建议复用

- `wireframe_wavefront`
- `wireframe_pulses`
- `wireframe_ridge`
- 以及所有“左右边缘发射 + 向中间传播”的具体视觉内核

结论：

- 平台保留
- 渲染内核重写

## 下一轮讨论建议顺序

### 1. 先定视觉对象

优先在下面三者中选一个：

- 单一二维共振板
- 多个共振体阵列
- 介质/粒子/纤维场

当前建议优先：

- 单一二维共振板，或少量共振板阵列

### 2. 再定显示形式

可能的显示层：

- 结线
- 等值线
- 位移亮度场
- 颗粒聚集
- 细线 contour

当前建议优先：

- 黑底白线的等值线 / 结线风格
- 不做大面积实色填充

### 3. 最后定驱动方式

需要讨论的是：

- 是用频带驱动模态
- 还是直接用更低层的时域/短时频域信号驱动二维场

当前建议：

- 不追求“完全零处理”
- 允许做最低限度的频带/模态耦合
- 但避免回到 `beat/onset/段落` 主导的语义映射

## 建议的新主题命名

可作为下一轮起点的候选名称：

- `chladni_field`
- `resonance_field`
- `modal_plate`
- `resonance_array`

当前建议优先：

- `chladni_field`

## 进入新会话时的建议起点

新会话里建议直接从下面这个目标开始：

> 设计并实现一个 `chladni_field` 主题。它不是波形或频谱的直接图表，而是一张被复杂音乐持续激发的二维共振板。画面以黑底白线为主，不做大面积实色填充，重点表现模态迁移、结线变化和能量在板面上的重新分布。
